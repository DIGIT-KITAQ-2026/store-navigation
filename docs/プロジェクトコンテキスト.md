# プロジェクトコンテキスト

このファイルは、誰が(どのメンバーが)Claudeとのチャットを開いても同じ前提を共有できるように、
これまでの検討で決まったことをまとめたものです。`CLAUDE.md` から常に読み込まれます。

## WHAT — 何を作るか

スーパーやコンビニで商品を検索し、店内ナビゲーションまで完結できるスマホアプリ(ハッカソン向けMVP)。
詳細は `docs/仕様書.md`、見た目・UIのルールは `DESIGN.md` を参照。

- 対象は単一のデモ店舗のみ(マルチテナント化は将来対応)
- 消費者用: QRコードでの入店・位置取得 → AIによる自然文商品検索 → Unity WebGLでの3Dナビゲーション
- 管理者用: ログイン、棚バーコード×商品バーコードでの商品登録/削除、商品一覧

## WHY — なぜこの構成か

- 店員に話しかけずに探し物を見つけられるようにし、消費者・店員双方の負担を減らすため
- 屋内はGPSが使えないため、入口の「スタート地点QRコード」を基準にした固定ルート表示を採用
   (リアルタイム位置追跡はスコープ外)
- AI検索は当初「Claude Agent SDKをclaude.aiサブスクリプションのOAuth認証で使う」想定だったが、
  実装初期の検証でAnthropicの利用ポリシー上不可と判明(サードパーティ製品へのclaude.aiログイン
  組み込みは原則禁止)。代わりに`claude`コマンド(Claude Code CLI)をNext.js API routeから
  サブプロセス実行する方式に変更した。Anthropic APIキー(従量課金)は引き続き契約しない方針で、
  `claude login`/`claude setup-token`によるサブスクリプション認証を利用する。詳細・残課題は
  `docs/仕様書.md`の「AI連携仕様」を参照

## 体制・進め方について

チームは5人、Gitを使った共同開発はほぼ全員が未経験。当初、各自が `main` を共有しないまま
個人のフォルダでバラバラに作業を始めてしまった経緯がある。これを踏まえて次を整備済み。

- `CONTRIBUTING.md`: 1人1機能ブランチ+PRの運用ルール、コンフリクト対応の基本手順
- `.claude/skills/merge-folder/`: バラバラな作業フォルダを、確認を取りながら新規ブランチとして
  安全に取り込むスキル(`/merge-folder <フォルダパス>`)
- `TASK.md` / `.claude/skills/manage-tasks/`: 誰でも取れる共有タスクバックログと、
  仕様書・DESIGN.mdと実コードを照合した未実装タスクの自動提案スキル(`/manage-tasks`)

新しく参加する・久しぶりに戻ってきたメンバーは、まず `CONTRIBUTING.md` を読み、
`/manage-tasks` で今何が残っているかを確認してから着手する。
