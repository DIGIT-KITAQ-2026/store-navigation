# デプロイ手順(Vercel + 外部推論サーバー)

## なぜこの構成なのか

このアプリは、意味検索・画像検索・音声認識のモデルをサーバー側で動かしている。

| モデル | 用途 | サイズ |
|---|---|---|
| ruri-v3-30m | 日本語の意味検索 | 145MB |
| multilingual-e5-small | 英語・中国語・韓国語の意味検索 | 448MB |
| CLIP vit-base-patch32 | 画像検索 | 578MB |
| whisper-ja-760M | 音声文字起こし | 1.1GB |
| | 合計 | 約2.3GB |

Vercelのサーバーレス関数は書き込み先が `/tmp` の512MBまでで、関数バンドルも250MB上限。
このモデルを置く場所が無い。商品説明文の生成で使う `claude` コマンドも、
サブプロセスとして起動できない。

そこで**AI処理だけを常時稼働している別マシンへ転送する**。

```
ブラウザ → Vercel(画面・DB) → Cloudflare Tunnel → 推論サーバー(モデル実行)
```

`AI_INFERENCE_BASE_URL` が未設定なら転送せず、そのプロセス内でモデルを実行する。
つまりローカル開発や自前サーバー1台での運用では、この構成を意識しなくてよい。

## 手順

### 1. 推論サーバーを用意する

常時起動しておけるマシン(ノートPCでも可)で作業する。

```bash
git clone <このリポジトリ>
cd store-navigation
npm ci
cp .env.local.example .env.local
```

`.env.local` に次を設定する。

- `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- `AI_INFERENCE_SHARED_SECRET`(下で生成する値)
- `AI_INFERENCE_BASE_URL` は**空のまま**(ここはモデルを実行する側なので転送しない)

共有シークレットを生成する。

```bash
openssl rand -hex 32
```

`claude` コマンドを使う機能(商品説明文の生成)も動かすなら、このマシンで `claude login` しておく。

起動する。

```bash
npm run build
npm start
```

初回はモデルのダウンロードに時間がかかる(合計2.3GB)。
`http://localhost:3000` で検索が動くことを確認してから次へ進む。

### 2. トンネルで公開する

**ngrokの固定ドメインを使う(推奨)**

無料アカウントで固定ドメインが1つもらえる。URLが変わらないので、
Vercel側の設定は初回だけで済み、以降は再デプロイが不要になる。

1. https://dashboard.ngrok.com で登録し、Domains から固定ドメインを1つ取得する
2. Your Authtoken からトークンをコピーする

```bash
brew install ngrok
ngrok config add-authtoken <トークン>
ngrok http 3000 --url=<取得したドメイン>.ngrok-free.app
```

このドメインはアカウントに永久に割り当てられ、しばらく使わなくても消えない。
PCを再起動しても同じコマンドで同じURLに戻る。

**Cloudflareの一時トンネルを使う場合**

```bash
brew install cloudflared
cloudflared tunnel --url http://localhost:3000
```

`https://xxxx-xxxx.trycloudflare.com` が表示される。アカウント登録が要らない代わりに、
**URLが毎回変わる。** 変わるたびにVercel側の環境変数の更新と再デプロイが必要になるので、
発表前に張り直すと事故りやすい。固定したい場合は名前付きトンネルにできるが、
Cloudflareで管理している独自ドメインが必要になる。

### 3. Vercel側を設定する

Vercelのプロジェクト設定 → Environment Variables に追加する。

| 変数 | 値 |
|---|---|
| `AI_INFERENCE_BASE_URL` | 手順2のURL(末尾のスラッシュなし) |
| `AI_INFERENCE_SHARED_SECRET` | 手順1で生成した値と**同じもの** |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabaseの値 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 同上 |
| `SUPABASE_SERVICE_ROLE_KEY` | 同上 |

デプロイするブランチを `deploy/kota-ai-search-on-hybrid` にする。
環境変数を追加・変更したら**再デプロイが必要**(既存のデプロイには反映されない)。

### 4. 動作を確認する

Vercelの本番URLで、抽象的な検索を試す。

- 「小腹が空いた」→ ポテトスナック・ビスケットが出れば成功
- 「AI検索が一時的に利用できないため…」と出たら失敗(下記参照)

### 5. 10月末まで連続稼働させる

検索画面だけが表示できても、`usedFallback: true` なら意味検索は停止している。このため、
トップページではなく実際の検索APIを定期的に監視する。

#### 最低限: 推論サーバーMacを自動復旧させる

推論サーバーMacで次を一度だけ実行する。

```bash
./scripts/install-ai-watchdog.sh
```

ログイン時と5分ごとに `小腹が空いた` の本番検索を実行し、意味検索が失敗した場合は
`npm start` と固定ngrokトンネルを起動し直す。ログは `scripts/.demo-logs/watchdog.log` に残る。
自動復旧できない場合はmacOS通知も出る。

このMacは、10月31日までは次を守る。

- 電源につなぎ、ふたを閉じず、スリープを許可しない（起動スクリプトは `caffeinate` を使う）
- 自動ログインは不要だが、OS再起動後には一度ログインする（LaunchAgentを動かすため）
- 固定ngrokドメイン・ngrok認証情報を削除しない
- デモ直前だけでなく、`./scripts/health-check.sh` が成功することを毎日確認する

監視は短時間のプロセス停止やトンネル切断を自動復旧するが、PC故障・停電・自宅回線断までは
単一Macでは防げない。発表や常時公開で「AI機能を落とさない」必要がある場合は、次の待機系も
必ず用意する。

#### 推奨: 主系・待機系の2台構成にする

別の電源・別のネットワークにある2台目の推論サーバーを、手順1〜2と同じように起動する。
両方の `.env.local` には同じ `AI_INFERENCE_SHARED_SECRET` を設定し、**両サーバー側では**
`AI_INFERENCE_BASE_URL` を空のままにする。

Vercelの `AI_INFERENCE_BASE_URL` だけを、主系・待機系の固定URLをカンマ区切りで設定する。

```text
https://primary.example.com,https://standby.example.com
```

アプリは左から順に呼び出し、主系の接続失敗または5xx時に待機系へ自動で切り替える。
この環境変数を変えた後はVercelを必ず再デプロイする。両系が稼働中でも、Vercelの設定漏れ・
シークレット不一致は自動修復できないため、変更後に `./scripts/health-check.sh` で実検索を確認する。

#### Supabaseも検索の必須依存先として監視する

AIモデルの前に、検索APIはSupabaseから商品カタログを取得する。`店舗・商品情報の取得に失敗しました`
という500は、推論サーバーを再起動しても直らない。Supabase Dashboardで次を確認する。

- プロジェクトが有効で、`NEXT_PUBLIC_SUPABASE_URL` のホスト名が現在のプロジェクトURLと一致する
- `SUPABASE_SERVICE_ROLE_KEY` をVercelと推論サーバーの両方で更新し、Vercelを再デプロイした
- Data APIで `stores`、`products`、`shelves`、`shelf_locations`、`categories`、`category_keywords`、
  `inventory_counts` が公開対象になっている

Supabaseは2026年10月30日から、publicスキーマのテーブルをData APIへ明示的に公開する設定を
全プロジェクトで強制する予定である。期限前に上記の公開状態を確認する。

## うまくいかないとき

### 「AI検索が一時的に利用できないため、通常検索の結果を表示しています」

意味検索が例外を投げて、文字列一致だけの検索に切り替わっている。原因は次のどれか。

1. `AI_INFERENCE_BASE_URL` が未設定、または設定後に再デプロイしていない
2. 推論サーバーが落ちている、トンネルのURLが変わっている
3. `AI_INFERENCE_SHARED_SECRET` が両側で一致していない(推論サーバーが403を返す)

推論サーバー側のログに `/api/internal/*` へのアクセスが出ているかを見ると切り分けられる。
アクセスが無ければ1か2、403が出ていれば3。

### 検索は動くが音声・画像だけ動かない

推論サーバーのモデルが揃っていない可能性がある。
`/api/internal/transcribe` と `/api/internal/embed-image` を初めて叩いたときに
ダウンロードが走るので、初回は1分ほど待つ。

## 別案: 推論サーバー1台だけで運用する

Vercelを使わず、アプリ全体を推論サーバーで動かしてトンネルで公開してもよい。
この場合 `AI_INFERENCE_BASE_URL` は空のままでよく、ブランチも `develop` のままでよい。

```bash
npm run build && npm start
cloudflared tunnel --url http://localhost:3000
```

手順が少なく、環境変数の同期も不要。デモだけならこちらの方が確実。
欠点はそのマシンを起動し続ける必要があることと、一時トンネルのURLが毎回変わること。

## 転送されるデータについて

音声はFloat32の配列をJSONにして送っている(`/api/internal/transcribe`)。
5秒の音声で8万個の数値になり、1リクエストあたり1MB以上になる。
トンネル越しだと転送だけで数秒かかることがあるので、
デモ前に一度音声検索を実行してモデルを温めておくとよい
(初回はモデルの読み込みで1分ほどかかる)。
