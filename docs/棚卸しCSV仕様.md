# 棚卸しCSV仕様

管理者画面(`/admin/inventory`)から取り込む棚卸し(実地在庫確認)CSVの列仕様・検証内容を
まとめたもの。データベース側の設計は[`docs/データベース設計.md`](./データベース設計.md)
8節を参照。

## 1. 列仕様

列名は英字固定。1行目はヘッダー行で、列の並び順は問わない(列名で位置を特定する)。

### 必須列

| 列名 | 内容 |
|---|---|
| `store_code` | 店舗コード。`stores.entry_qr_code`と一致する必要がある(ログイン中の管理者の担当店舗のものだけを受け付ける) |
| `shelf_code` | 棚位置コード。`shelf_locations.location_code`(`Shelf_01`〜`Shelf_08`)と一致する必要がある |
| `sku` | 棚卸し側の管理番号(任意の文字列。`products`テーブルの列ではない) |
| `product_name` | 商品名(表示・確認用) |
| `category_code` | カテゴリコード(`CAT_01`〜`CAT_08`) |
| `actual_stock` | 実地在庫数(0以上の整数) |
| `counted_at` | 棚卸し日時。`YYYY-MM-DD`または`YYYY-MM-DD HH:mm`・`YYYY-MM-DD HH:mm:ss`(`T`区切りも可)。**UTCとして解釈する**(JSTのつもりで入力する場合は時刻を明示し、必要に応じて調整すること) |

### 任意列

| 列名 | 内容 |
|---|---|
| `jan_code` | 商品バーコード。`products.barcode`との突き合わせに使う。空欄の場合は商品未登録行として扱う |
| `book_stock` | 帳簿在庫数(空欄または0以上の整数) |
| `unit` | 単位(自由文字列) |
| `cost_price` | 原価(空欄または0以上の数値) |
| `selling_price` | 売価(空欄または0以上の数値) |

## 2. 取込フロー

```
CSVファイルを選択
  ↓ クライアント側で読み込み、基本形式はあくまで参考程度に見る
プレビューAPI(POST /api/admin/inventory/preview)
  ↓ サーバー側で全項目を再検証(クライアント側の結果は信用しない)
プレビュー結果(行ごとのステータス・理由)を確認
  ↓ 利用者がエラー行を確認・CSVを修正
確定API(POST /api/admin/inventory/import)
  ↓ 同じ検証をサーバー側でもう一度実行してから保存
inventory_countsへ保存
```

プレビューAPIは何も保存しない。確定APIは、その時点のCSVを**再度**検証し、1件でも
エラー行があれば何も保存せず中断する(一部の行だけ保存された中途半端な状態を避けるため)。

## 3. 行ごとの判定

| ステータス | 意味 | inventory_countsへの保存 |
|---|---|---|
| OK | 問題なし | 保存する |
| 要確認(warning) | 保存はできるが注意が必要 | 保存する(`product_id`は`NULL`) |
| エラー(error) | この行は保存できない | 保存しない(1件でもあれば確定処理全体を中断) |

### エラーになる条件

- 必須列(`store_code`/`shelf_code`/`sku`/`product_name`/`category_code`/`actual_stock`/`counted_at`)が空
- `store_code`がログイン中の管理者の担当店舗と一致しない
- 同一CSV内で`sku`が重複している
- `category_code`が有効なカテゴリ(`is_active = true`)に見つからない
- `shelf_code`が見つからない、または他店舗の棚である
- `actual_stock`が0以上の整数でない
- `book_stock`/`cost_price`/`selling_price`が指定されているのに数値として不正
- `counted_at`が指定の日時形式でない、または実在しない日時(例: 2月30日)
- `jan_code`で商品が見つかったが他店舗の商品である
- `category_code`から求めたカテゴリが、その棚(`shelf_locations.category_id`)または
  商品(`products.category_id`、設定済みの場合のみ)のカテゴリと一致しない
- 列の数がヘッダー行と一致しない行

### 要確認(warning)になる条件

- `jan_code`が空、または`products.barcode`と一致する商品が見つからない
  (`product_id`は`NULL`のまま棚卸しデータとして保存される。カテゴリ・棚番の妥当性を
  商品側からは確認できないため、誤案内につながらないよう自動登録はしない)

## 4. 商品未登録SKUの扱い

商品未登録(`jan_code`が空、または一致する商品がない)のSKUを**自動で`products`へ登録する
ことはしない**。理由:

- カテゴリ・棚番が正しいか商品側の情報で確認できない
- 商品説明やバーコードが不足している可能性がある
- 誤った内容のまま登録すると誤案内につながる

このようなSKUは棚卸しデータとしては保存されるが、実際の商品登録は
`/admin/products/new`から別途行う。

## 5. 制限事項

- 文字コードはUTF-8(BOM付き含む)またはCP932(Shift_JIS)に対応する
  (`src/lib/inventory/decodeCsvBytes.ts`)。ファイルはバイト列のままプレビュー/確定APIへ送り、
  サーバー側でUTF-8として妥当かをまず判定し、UTF-8として不正な場合だけCP932として解釈する。
  どちらとしても不正なバイト列はエラーとして取込を拒否し、「UTF-8またはShift_JISのCSVを
  使用してください」と表示する(文字化けした文字列を後処理で置換・推測することはしない)
- ファイルサイズ・データ行数に上限がある(概ね2MB・2000行。超える場合は分割すること)
- CSVは空にできない。ヘッダー行のみ(データ行が0件)もエラーになる

## 6. CSV数式インジェクション対策

`=`・`+`・`-`・`@`で始まるセルの値をスプレッドシートで開くと数式として実行される
危険がある(CSVインジェクション)。プレビュー画面に表示する際、これらの文字で始まる値は
先頭にシングルクォート(`'`)を付けて無害化して表示する(`src/lib/inventory/csvInjection.ts`)。
保存する値そのものは書き換えない(商品名を不必要に破壊しないため)。

## 7. サンプルCSV

[`public/samples/inventory-count-sample.csv`](../public/samples/inventory-count-sample.csv)
(`/admin/inventory`画面からもダウンロードできる)。歯ブラシ・ノート・乾電池・化粧用パフ・
圧縮袋・掃除用スポンジ・保存容器・菓子(それぞれ末尾に「(デモ)」を付けている)の8行で、
8カテゴリすべてを1行ずつ含む。秘密情報・実在企業の情報は含まない。`jan_code`は空欄にしており、
「商品未登録(要確認)」のプレビュー表示を確認する例にもなっている。

このファイルはWindows版Excelでダブルクリックしても日本語が文字化けしないよう、
UTF-8 BOM付きで保存している(再生成する際もBOMを落とさないこと)。取込側の
`decodeCsvBytes`はBOMの有無に関わらずUTF-8・CP932(Shift_JIS)を読み込めるため、
本ファイルへのBOM付与は取込・プレビュー処理に影響しない。

## 9. 在庫状態表示(検索結果・商品案内・3D案内への反映)

取り込んだ棚卸しデータは、以下の3状態として検索結果カード・商品案内画面(`GuidePanel`)・
3D目的地カード(`RealisticStoreControls`)へ表示する(`src/lib/inventory/stockStatus.ts`)。

| 状態 | 記号 | 判定 |
|---|---|---|
| 在庫あり | ○ | 対象の最新`actual_stock` > 0 |
| 在庫なし | × | 対象の最新`actual_stock` === 0 |
| 在庫情報なし | － | 対象の最新棚卸データが無い |

記号・色だけに依存せず、必ずラベル文言も併記する。

**最新在庫の解決方法**(`src/lib/inventory/latestStock.ts`): 商品ごとに、
①`product_id`が一致する棚卸し行の最新(`counted_at`降順、同時刻は`created_at`降順)を最優先し、
②無ければ同じ棚(`shelf_location_id`一致かつ`product_id IS NULL`)の棚卸し行の最新へフォールバックする。
②は`jan_code`が空、または一致する商品が無い(3節の「要確認」)行を商品未登録のまま棚卸しデータとして
保存する設計(4節参照)を踏まえた実装判断であり、本仕様書に別途明記された挙動ではない点に注意する。

3D目的地カードは、案内先として最初に選ばれた売り場を表示している間だけ在庫状態を表示する
(利用者が「売り場を選択」で別の売り場に切り替えた場合は、その売り場自身の在庫情報を
再取得していないため表示しない)。Canvasの再マウント・GLBの再取得・BFS/経路計算は
在庫状態の表示によって一切変更しない。
