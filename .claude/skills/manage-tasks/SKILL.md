# /manage-tasks — 共有タスクバックログの管理

`TASK.md` をチーム全員の共有バックログとして表示・更新する。担当者の割り振りは行わない
(誰でも好きなタスクを取ってよい運用)。

## 引数の解釈

`$ARGUMENTS` を見て次のいずれかとして扱う。

- 空、または「見せて」「教えて」「一覧」などの表示要求 → **表示モード**
- `add <タスク内容>` または「〜を追加して」 → **追加モード**
- `done <タスク内容 または番号>` または「〜終わった」「〜完了」 → **完了モード**

## 表示モード

1. リポジトリ直下の `TASK.md` を読む(無ければ以下のひな形で新規作成する)。

   ```markdown
   # TASK

   ## 未完了
   
   ## 完了
   ```

2. `docs/仕様書.md` と `DESIGN.md` を読み、そこに書かれている画面・機能(消費者用検索/AI連携/
   Unityナビゲーション、管理者用ログイン/商品登録/商品削除/商品一覧、データモデルなど)を洗い出す
3. 実際のリポジトリのコード(`app/` や `pages/` などのNext.jsのルーティング、コンポーネント、
   DB定義やAPI routeの有無)を確認し、2で洗い出した項目のうちまだ実装されていなさそうなものを判断する
4. 3で見つかった未実装項目のうち、`TASK.md` の未完了セクションに**まだ載っていないもの**だけを
   「(自動検出)」を付けて追記する(既にある項目と重複させない。表現が近い項目は重複とみなす)
5. 更新後の `TASK.md` の内容(未完了・完了それぞれ)をユーザーに分かりやすく提示する

## 追加モード

- 指定された内容を `TASK.md` の未完了セクションに `- [ ] <内容>` として追記する
- 自動検出のタスクと紛れないよう、自動検出でないことが分かる表記にする(「(自動検出)」は付けない)

## 完了モード

- 指定された内容に一致(または最も近い)未完了タスクを未完了セクションから削除し、
  完了セクションに `- [x] <内容>` として追記する
- 一致するタスクが複数/曖昧な場合は、候補を挙げてユーザーに確認する

## 注意

- `TASK.md` はチーム共有のファイルなので、既存の記述(手動で書かれたメモ書きなど)を勝手に
  書き換えたり要約し直したりしない。追記・チェック状態の更新のみ行う
- 自動検出はあくまで「提案」であり、実際に対応するかはチームの判断に委ねる
